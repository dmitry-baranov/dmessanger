# План frontend-разработки Flutter Android

## Цель frontend

Собираемое Android-приложение на Flutter, которое позволяет заранее созданному пользователю войти, видеть список чатов, отправлять сообщения и медиа, принимать realtime-события и совершать защищённые звонки.

## Основные экраны

### Auth

- Экран входа: login/password.
- Экран ошибки авторизации.
- Автоматический вход по refresh token, если сессия активна.

### Chat list

- Список личных и групповых чатов.
- Последнее сообщение.
- Время последнего события.
- Индикатор непрочитанных сообщений.
- Индикатор online для личного чата.

### Chat screen

- История сообщений.
- Отправка текста.
- Отправка фото/видео из галереи.
- Превью вложений перед отправкой.
- Индикаторы доставки и прочтения.
- Typing indicator.
- Кнопка аудио/видео звонка.

### Call screen

- Входящий звонок.
- Исходящий звонок.
- Активный звонок.
- Mute/unmute microphone.
- Enable/disable camera.
- Speaker mode.
- Завершить звонок.
- Для группового звонка — сетка участников.

### Settings

- Текущий пользователь.
- Выход.
- Диагностика соединения.
- Управление локальными ключами только в debug/dev режиме.

## State management

Рекомендуемый вариант для MVP — Riverpod:

- `AuthController` — состояние авторизации.
- `ChatListController` — список чатов.
- `MessageController` — история конкретного чата.
- `WebSocketController` — lifecycle realtime-соединения.
- `CallController` — состояние звонка.
- `AttachmentController` — загрузка и отправка медиа.

## Локальное хранение

### Secure storage

В `flutter_secure_storage` хранить refresh token, device private identity key, private signed pre-key, локальные секреты E2EE.

### Local database

В Drift хранить список чатов, участников, сообщения, статусы доставки, метаданные вложений и очередь исходящих сообщений.

Если хранится plaintext локально, локальная база должна быть зашифрована. Более безопасный вариант — хранить ciphertext и кэшировать plaintext только в памяти.

## Realtime flow

1. После логина приложение открывает WebSocket.
2. Backend подтверждает соединение и отправляет актуальное состояние.
3. При новом сообщении приходит событие `message.created`.
4. Клиент сохраняет событие локально, расшифровывает сообщение и обновляет UI.
5. Клиент отправляет `message.delivered`.
6. При открытии чата клиент отправляет `message.read`.

## Отправка сообщения

1. Пользователь вводит текст.
2. Клиент находит активную E2EE-сессию с каждым устройством получателя.
3. Текст шифруется на клиенте.
4. Клиент отправляет ciphertext на backend.
5. Backend сохраняет ciphertext и рассылает realtime-событие получателям.
6. Получатель расшифровывает сообщение локально.

## Отправка фото/видео

1. Пользователь выбирает файл.
2. Клиент генерирует случайный file key.
3. Файл шифруется локально.
4. Клиент запрашивает upload URL у backend.
5. Клиент загружает зашифрованный файл в MinIO.
6. В сообщении отправляется attachment metadata и зашифрованный file key для получателей.

## Звонки

Для звонков использовать `flutter_webrtc`.

### 1:1 звонок

1. Caller создаёт call session через backend.
2. WebSocket отправляет событие входящего звонка callee.
3. Клиенты обмениваются SDP offer/answer через backend signaling.
4. ICE candidates передаются через WebSocket.
5. Media stream идёт напрямую или через TURN.
6. Завершение звонка фиксируется через WebSocket/REST.

### Групповой звонок

MVP-вариант — mesh: каждый участник держит WebRTC-соединение с каждым другим участником. Ограничить количество участников, например 4. Если групповые звонки должны стать основной функцией, нужен SFU.

## Definition of Done для frontend MVP

- APK собирается локально.
- Пользователь входит по логину и паролю.
- Пользователь видит список доступных чатов.
- Пользователь отправляет и получает текстовые сообщения.
- Пользователь отправляет и получает фото.
- Пользователь отправляет и получает видео.
- Realtime работает через WebSocket.
- 1:1 звонок работает между двумя Android-устройствами.
- Все чувствительные токены и ключи хранятся в secure storage.
